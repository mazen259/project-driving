# 🚗 الرخصة — مساعد ذكي لتعليم السواقة في مصر

مساعد محادثة (Chatbot) يعمل بتقنية **RAG (Retrieval-Augmented Generation)** باللغة العربية، مبني على **FastAPI** من الخلف و**HTML/CSS/JS** بسيط من الأمام، ويجاوب على أسئلة المستخدمين حول:

- 📋 إجراءات استخراج رخصة القيادة في مصر (النظري والعملي)
- 🏫 مدارس/مدربين السواقة المتاحين، مناطقهم، ومحافظاتهم، وأرقام هواتفهم
- 🔧 أسعار صيانة السيارات حسب سعة المحرك ونوع الخدمة والمدينة

---

## ✨ المميزات

- **بحث ذكي مُعرَّب (Arabic-aware retrieval):** تطبيع للنص العربي (إزالة التشكيل، توحيد الألف/الياء/التاء المربوطة...) قبل الفهرسة والبحث، عشان الفروق الإملائية زي "مدرسة" و"مدرسه" ما تأثرش على نتائج البحث.
- **TF-IDF مع n-grams (1-3):** لفهم العبارات مش بس الكلمات المفردة، بالإضافة لدعم اختياري لباك إند **Embeddings** (sentence-transformers) للبحث الدلالي الأعمق.
- **Hybrid Boosting:** لو السؤال فيه رقم سعة محرك معروف (زي 1600) أو اسم منطقة/محافظة معروف، الأجزاء (chunks) اللي فيها نفس القيمة بالظبط بتاخد وزن إضافي في الترتيب.
- **Domain Routing:** تصنيف مبدئي للسؤال (رخصة / مدرسة / صيانة) قبل عمل البحث، عشان يمنع تسريب نتائج من مجال لمجال تاني (زي سؤال عن الصيانة يرجّع مدارس سواقة بالغلط).
- **دعم المحادثة متعددة الأدوار (Multi-turn):** الباك إند بيستقبل تاريخ المحادثة كامل عشان يفهم الأسئلة التابعة زي "وإيه بعد كده؟".
- **كاش للـ Embeddings على القرص:** لو استخدمت باك إند الـ embeddings، النتائج بتتخزن كاش (fingerprint من البيانات + اسم الموديل) عشان السيرفر ما يعيدش الحساب في كل مرة يشتغل فيها.
- **دعم أكتر من مزوّد LLM:** `llm_client.py` بيستخدم **Groq** (llama-3.3-70b-versatile) كموديل أساسي، وموجود كمان `gemini_client.py` كبديل جاهز لو حبيت تستخدم Gemini.
- **واجهة أمامية جاهزة:** صفحة شات واحدة (`index.html`) بتصميم مستوحى من لافتات الطرق المصرية، متصلة مباشرة بالـ API.

## ⚙️ طريقة التشغيل

### 1. تجهيز البيئة الافتراضية وتثبيت المتطلبات

```bash
cd backend
python -m venv venv
venv\Scripts\activate        # على ويندوز
# أو: source venv/bin/activate   على ماك/لينكس

pip install -r requirements.txt
```

### 2. إعداد ملف `.env`

المشروع فيه ملف `backend/.env.example` بس (كـ Template)، وده اللي المفروض تعتمد عليه — ملف `.env` نفسه **مش لازم يكون موجود ضمن المشروع/الريبو** لأنه بيحتوي على المفاتيح الحقيقية بتاعتك ومفيش داعي لمشاركته أو رفعه.

اعمل نسخة منه باسم `.env` واملأ القيم الحقيقية فيها:

```bash
cd backend
cp .env.example .env      # على ماك/لينكس
copy .env.example .env    # على ويندوز (Command Prompt)
```

ثم افتح `backend/.env` واملأ القيم فعليًا (خصوصًا `GROQ_API_KEY`):

> ملحوظة: ملف `.gitignore` في المشروع بالفعل مضبوط عشان يتجاهل `.env` (ومعاه أي `*.env`) ويستثني `.env.example` فقط — يعني لو رفعت المشروع على Git، ملفك الشخصي بمفاتيحك مش هيترفع بالغلط.

| المتغير | الوصف | القيمة الافتراضية |
|---|---|---|
| `GROQ_API_KEY` | مفتاح API الخاص بـ Groq (**مطلوب** لتشغيل المحادثة) | - |
| `GROQ_MODEL` | اسم الموديل المستخدم على Groq | `llama-3.3-70b-versatile` |
| `RETRIEVAL_BACKEND` | `tfidf` (افتراضي، سريع ومحلي) أو `embeddings` (بحث دلالي) | `tfidf` |
| `EMBEDDING_MODEL` | اسم موديل sentence-transformers (لو استخدمت `embeddings`) | `paraphrase-multilingual-mpnet-base-v2` |
| `EMBEDDING_CACHE_DIR` | مكان تخزين كاش الـ embeddings | `backend/app/.cache` |
| `FORCE_REEMBED` | إجبار إعادة حساب الـ embeddings من الصفر | `false` |

### 3. تشغيل السيرفر

```bash
uvicorn app.main:app --reload --port 8000
```

ثم افتح المتصفح على:

```
http://localhost:8000
```

الفرونت إند بيتقدم من نفس السيرفر (مفيش حاجة إضافية تشغّلها للواجهة).

## 🚀 تطويرات مستقبلية ممكنة

1. **قاعدة بيانات حقيقية بدل ملف نصي:** نقل `all_data.txt` إلى قاعدة بيانات (PostgreSQL/SQLite) مع واجهة إدارة (Admin) لإضافة/تعديل المدارس وأسعار الصيانة بدون التعديل اليدوي في ملف نصي.
2. **دعم صوتي (Speech-to-Text / Text-to-Speech):** إضافة إمكانية سؤال المساعد بالصوت والرد صوتيًا، مفيد جدًا لفئة كبيرة من المستخدمين.
3. **Caching لإجابات الأسئلة المتكررة:** تخزين مؤقت (in-memory أو Redis) لأزواج (سؤال مطبّع → إجابة) لتقليل تكلفة استدعاء الـ LLM على الأسئلة المتكررة بكثرة.
4. **مراقبة وتسجيل (Logging & Monitoring):** تسجيل الأسئلة، درجات التشابه، والوقت المستغرق، لتحليل جودة الاسترجاع وتحسين حدود الـ threshold بناءً على بيانات حقيقية.
5. **دعم رفع الصور/المستندات:** مثلاً رفع صورة رخصة أو استمارة والتحقق منها أو استخراج بيانات منها.
6. **اختبار A/B بين `tfidf` و `embeddings`:** لوجود الباك إندين جاهزين بالفعل، ممكن تقييم أيهم أدق فعليًا على أسئلة حقيقية قبل اعتماد واحد نهائي في الإنتاج.

## 📌 ملاحظات تقنية

- الفهرسة (`RagIndex`) بتتبني مرة واحدة بس عند تشغيل السيرفر (`lifespan` في `main.py`)، فأي تعديل على `all_data.txt` محتاج إعادة تشغيل السيرفر.
- لو غيّرت `RETRIEVAL_BACKEND` لـ `embeddings`، أول تشغيل هيكون أبطأ (تنزيل الموديل + حساب الـ embeddings)، والتشغيلات اللي بعد كده هتكون سريعة بسبب الكاش.
