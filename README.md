# الرخصة — مساعد تعليم السواقة (Driving School RAG Assistant)

مشروع RAG (Retrieval-Augmented Generation) احترافي يجمع بين:
- قاعدة معرفة عن إجراءات استخراج رخصة القيادة في مصر
- قائمة مدارس/مدربين السواقة (الاسم، الهاتف، المنطقة، المحافظة)
- بيانات أسعار صيانة السيارات

ويستخدم **Groq API** (نموذج Llama 3.3 70B) لتوليد إجابات دقيقة بالعربية
بناءً على البيانات المسترجعة فقط، مع واجهة ويب احترافية بثلاث تبويبات
(محادثة، دليل المدربين، حاسبة الصيانة) متصلة عبر **FastAPI**.

## هيكل المشروع

```
driving-rag/
├── backend/
│   ├── app/
│   │   ├── main.py            # تطبيق FastAPI (API + تشغيل الواجهة)
│   │   ├── rag.py             # فهرسة TF-IDF + تطبيع عربي + hybrid boosting
│   │   ├── llm_client.py      # الاتصال بـ Groq API + ذاكرة المحادثة
│   │   ├── data_loader.py     # قراءة وتحويل ملف البيانات الخام
│   │   └── __init__.py
│   ├── data/
│   │   └── all_data.txt       # البيانات الخام (رخص + مدارس + صيانة)
│   ├── requirements.txt
│   └── .env.example
└── frontend/
    └── index.html              # واجهة بثلاث تبويبات (Dark theme, RTL)
```

## طريقة التشغيل

### 1. تجهيز البيئة

```bash
cd backend
python3 -m venv venv
source venv/bin/activate      # على Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. إضافة مفتاح Groq API

```bash
cp .env.example .env
```

ثم افتح ملف `.env` وضع مفتاحك الحقيقي (يمكن الحصول عليه مجاناً من
https://console.groq.com/keys):

```
GROQ_API_KEY=gsk_...
```

الملف يُقرأ تلقائياً عند تشغيل السيرفر — لا حاجة لكتابة المفتاح في التيرمينال.

### 3. تشغيل السيرفر

```bash
uvicorn app.main:app --reload --port 8000
```

ثم افتح المتصفح على: **http://localhost:8000**

الواجهة الأمامية (frontend) والـ backend يعملان معاً من نفس السيرفر — لا حاجة
لأي إعداد إضافي.

## ما الجديد في هذا الإصدار

**RAG أقوى:**
- تطبيع نصوص عربي (إزالة التشكيل، توحيد أشكال الألف/الياء/التاء المربوطة)
  قبل الفهرسة والبحث، فالبحث بقى مش حساس لاختلاف الإملاء
  ("مدرسة" = "مدرسه" = "مدرسة").
- فهرسة بـ n-grams من 1 إلى 3 كلمات مع sublinear TF لتقييم أدق للتشابه.
- Hybrid boosting: لو السؤال فيه سعة محرك محددة (زي "1600") أو اسم منطقة/مدينة
  معروف، بيتم رفع ترتيب النتائج اللي فيها نفس القيمة بالظبط.
- نقطة `/api/filters` بترجع كل القيم الفريدة (مناطق، محافظات، سعات، مدن)
  عشان الواجهة تستخدمها في قوائم منسدلة بدل كتابة نص حر.

**نموذج أقوى وذاكرة محادثة:**
- `llama-3.3-70b-versatile` على Groq — نموذج قوي بسياق كبير وجودة عربي عالية.
- المحادثة بقت "متذكرة" آخر الأسئلة (حتى 6 أدوار سابقة)، فالأسئلة المتابعة
  زي "وفي منطقة تانية؟" أو "وإيه بعد كده؟" بقت مفهومة بدون إعادة الشرح.

**واجهة احترافية بثلاث تبويبات:**
1. **المحادثة** — نفس الشات بس بذاكرة محادثة حقيقية.
2. **دليل المدربين** — فلترة مباشرة بالمحافظة والمنطقة، مع كارت لكل مدرب
   وزر اتصال مباشر (`tel:`).
3. **حاسبة الصيانة** — فلترة بسعة المحرك/نوع الخدمة/المدينة، وعرض جدول
   أسعار مرتب.

هوية بصرية مستوحاة من لافتات الطرق المصرية (الأزرق الليلي) ولون اللوحات
المعدنية (الذهبي)، بخط Cairo للعناوين وTajawal للنصوص.

## كيف يعمل RAG هنا

1. **الفهرسة (Indexing):** عند تشغيل السيرفر، يقرأ `data_loader.py` ملف
   `all_data.txt` ويحوّله إلى ثلاث مجموعات بيانات منظمة (إجراءات، مدارس،
   صيانة). ثم يبني `rag.py` فهرس TF-IDF عليها بعد تطبيع النص العربي.
2. **الاسترجاع (Retrieval):** عند وصول سؤال المستخدم، يتم تطبيعه، ثم البحث
   عن أقرب 8 مقاطع نصية له (تشابه الجيب التمام)، مع رفع ترتيب أي مقطع فيه
   تطابق حرفي لسعة محرك أو اسم مكان مذكور في السؤال.
3. **التوليد (Generation):** يتم إرسال المقاطع المسترجعة + سؤال المستخدم +
   آخر أدوار المحادثة إلى Groq، مع تعليمات صارمة بالاعتماد فقط على السياق،
   فيولد إجابة نهائية بالعربية.

## نقاط الـ API الرئيسية

| Method | Endpoint | الوظيفة |
|---|---|---|
| POST | `/api/chat` | إرسال سؤال (+ تاريخ المحادثة اختياري) والحصول على إجابة RAG + Groq |
| GET | `/api/schools?area=..&governorate=..` | فلترة مدارس السواقة مباشرة |
| GET | `/api/maintenance?engine_cc=..&service_type=..&city=..` | فلترة أسعار الصيانة مباشرة |
| GET | `/api/filters` | القيم الفريدة لتعبئة القوائم المنسدلة في الواجهة |
| GET | `/api/health` | التأكد أن السيرفر وقاعدة المعرفة تعمل |

## أفكار للتطوير لاحقاً

- استبدال TF-IDF بـ embeddings حقيقية لدقة أعلى في البحث الدلالي.
- إضافة قاعدة بيانات حقيقية (PostgreSQL/SQLite) بدل قراءة الملف كل مرة.
- إضافة تسجيل دخول وتقييم للمدربين من المستخدمين.
- نشر المشروع على منصة مثل Render أو Railway أو Fly.io.
